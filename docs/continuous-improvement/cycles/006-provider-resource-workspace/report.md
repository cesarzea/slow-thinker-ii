## Context and hypothesis

The owner activated three successive scopes as one complete delivery: a second
model provider, external components with calculator/memory, and a structured product
workspace. DeepSeek Flash and persistent private/shared key/value memory were
explicit selections. The existing S03 runtime, authoring, SDK and verified gates
were retained. P08–P10 predict reduced repeated shared-decision analysis and fewer
avoidable verification infrastructure failures. P11/P12 remain unapproved proposals.

Three implementers owned complete provider/preparation packages, resource/packaging
packages and frontend packages. The coordinator owned backend workspace/storage/HTTP,
shared contracts, fixtures, review and final verification. Exclusive ownership and
public dependency handoffs were established before development.

## Delivery and process results

Contracts, directory boundaries, public skeletons and module tickets preceded
exclusive parallel implementation. Individual receipts and whole-system source
review preceded functional test implementation. Shared HTTP/configuration fixtures
and representative composition/browser checks preceded dependent test expansion.
The same configured `make verify` entry point was retained throughout.

Preparation nevertheless omitted exact shared details that implementers needed:
workspace error/status and limits shapes, DeepSeek billing identity, a reviewed
holiday calendar, schema documents for local references and external-descriptor
validation. These required coordinator decisions during development. Necessary
public dependency comprehension is distinct from these missing shared decisions;
their respective effort was not measured.

Three full-runner attempts stopped at formatting, unsupported Node and CodeQL
respectively. The fourth completed: 2,203 Python tests, 340 frontend tests and 20
browser journeys, plus build, static/security, accounting mutation and independent
coverage gates. Scoped tests and correction reruns are additional activity, not
independent complete deliveries. A subsequent configuration audit found an accidental additional-importer
exemption on the existing derived example. The coordinator removed it and added
a real negative case: the violating import was accepted before correction and
rejected afterward. All 14 boundary probes and a fifth complete runner passed:
2,204 Python tests, 340 frontend tests and 20 browser journeys. This was a quality
configuration defect, not a runtime behavior defect; it was corrected before
publication. No required test incurred a provider charge.

Two separately authorized actual executions used both providers, installed external
workers, calculator and shared persistent memory. Independent checks reconcile
native usage and USD 0.000520600 cost, establish exact proposal/memory provenance
and preserve earlier revision results. The first model review returned a referral;
changed instructions produced a standalone plan in the next revision. This is
agent-quality evidence, not proof of comparative optimization.

## Evaluation and limitations

M06's phases, receipts and ownership were applied. Shared-decision omissions and
an installed bootstrap escape remain concrete weaknesses. A representative check
using real application ports and compiled plans did not establish installed host
bootstrap compatibility. The first actual demonstration detected that defect late,
although before any paid dispatch.

C05 covered personal JSON authoring; C06 covers three broader scopes and adds
actual provider/resource demonstrations. Neither has a reconciled effort audit.
Their checkpoint spans, package/test counts and participant overlap cannot prove
that the method saved time. The evidence supports specific preparation and
composition improvements; it does not establish overall productivity gains.
