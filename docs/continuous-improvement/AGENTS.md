# Maintaining engineering process improvement records

All maintained documents and authored evidence labels must be in English. Treat
this section as formal project documentation, with document identifiers, owners,
dates, status and traceable evidence. It evaluates the engineering process;
architecture and runtime contracts remain in their respective sections.

- Preserve method versions and closed-cycle records. Add later corrections as
  dated notes; retain original figures and conclusions and explain changes.
- When a relevant delivery cycle closes, use the cycle template and update the
  index. Do not create tasks, goals or automations merely to maintain this record.
- Distinguish approved decisions, observed practice and pending proposals.
- Separate elapsed time, pauses, accumulated parallel activity and retrospective
  activity estimates. Do not infer productivity from code volume or test counts.
- Record starting conditions, scope, outcomes and comparison limits. Different
  delivery periods are not a controlled experiment.
- Retain sufficient structured evidence to reconcile totals. Exclude credentials,
  commands containing local data and complete conversations.
- Preserve original source evidence separately and label translations of recorded
  statements. Record migration hashes in the provenance manifest; do not replace
  historical checksum claims with newly computed checksums.
- Current repository working rules remain authoritative. Archived rule snapshots
  are historical evidence and must not be treated as current instructions.
